# Firefox content script blocked by CSP (`Function()`) — a wxt version regression

v1.1.0 of enhanced-anime1 shipped on 2026-09-21. On Firefox the content script stopped
loading entirely; Chrome was unaffected. This is a minimal repro of why.

**Short version.** Same source, same lodash — two wxt versions, and one of them produces a
bundle Firefox refuses to run:

| | wxt | brings | lodash's `freeGlobal` | `Function('return this')()` |
|---|---|---|---|---|
| v1.0.1 | 0.20.7 | vite 6 + **rollup** | bound to an **injected `globalThis` shim** | never reached |
| v1.1.0 | 0.20.27 | vite 8 + **rolldown** | bound to a **bare `global`** | **reached — and blocked** |

rollup rewrote lodash's bare `global` into a shim; rolldown does not. The `rolldown` switch
is not a separate decision anyone made — it arrived with the wxt version.

lodash's `_root.js` ends with

```js
var freeGlobal = require('./_freeGlobal');
var freeSelf = typeof self == 'object' && self && self.Object === Object && self;
var root = freeGlobal || freeSelf || Function('return this')();
```

In the Firefox content-script sandbox both `freeGlobal` and `freeSelf` are falsy
([why](#why-firefox-and-not-chrome)), so with the newer wxt the third operand runs — during
module initialisation, before the entry point — and the MV3 extension CSP blocks it. The
content script dies completely rather than degrading.

## Repro

A wxt project whose only interesting property is that it imports lodash
([`repro/`](repro) — three small files, `keyBy` and nothing else). The wxt version is the
single variable; lodash is pinned to 4.17.21 in both.

```bash
bash reproduce.sh /tmp/wxt-repro           # builds both variants, prints fingerprints
node sandbox-sim.mjs /tmp/wxt-repro        # runs both bundles under a Firefox model
node verify.mjs /tmp/wxt-repro             # re-checks the fingerprints and byte slices
```

Observed:

| | wxt | toolchain | content script | `Function(` at | `global` shim |
|---|---|---|---|---|---|
| `old` | 0.20.7 | vite 6.4.3 + rollup 4.63.4 | 76,008 B<br>`967ff24fe327ac73…` | byte 6722 | **present** |
| `new` | 0.20.27 | vite 8.3.0 + rolldown 1.2.9 | 74,374 B<br>`e9c0e4c36e2a25d2…` | byte 5747 | **absent** |

Both builds are deterministic — the whole table reproduces byte-for-byte across runs — and
`expected.json` holds the same numbers so `verify.mjs` can fail loudly if a later transitive
dependency moves them.

`sandbox-sim.mjs` needs no browser. It lifts the verbatim `freeGlobal || freeSelf ||
Function(...)` chain out of each emitted bundle and evaluates it in a model of the Firefox
content-script sandbox:

```
 ok   wxt 0.20.7  (Vite 6 + rollup)    shim present  →  root = [object Object] — Function() not reached
 ok   wxt 0.20.27 (Vite 8 + rolldown)  shim absent   →  EvalError: call to Function() blocked by CSP
```

That is the same error the browser reported; the original console output is in
[`symptom/firefox-console.txt`](symptom/firefox-console.txt). The model is a model: it
encodes the realm split described below and the CSP's refusal, not Firefox's whole runtime.
The bundles and the byte slices are the real artifacts.

## The difference, in bytes

Exact slices of both bundles are in [`bundler-diff/`](bundler-diff), generated by
[`bundler-diff/make-slices.mjs`](bundler-diff/make-slices.mjs) from the built files — no hand
transcription, and `verify.mjs` re-checks that each slice is still a verbatim substring.

`old` — rollup emitted a shim, and `freeGlobal` reads *that*:

```js
var gn=typeof globalThis<"u"?globalThis:typeof window<"u"?window:typeof global<"u"?global:typeof self<"u"?self:{}
// later, in lodash's _root.js:
cu=typeof gn=="object"&&gn&&gn.Object===Object&&gn,zl=typeof self=="object"&&self&&self.Object===Object&&self,X=cu||zl||Function("return this")()
```

`new` — no shim anywhere in the bundle, so `freeGlobal` is a bare `global`:

```js
sn=typeof global==`object`&&global&&global.Object===Object&&global,cn=typeof self==`object`&&self&&self.Object===Object&&self,k=sn||cn||Function(`return this`)()
```

## Why Firefox and not Chrome

Firefox builds the content-script global as a fresh realm whose prototype is the page window,
with Xrays on (`Cu.Sandbox(..., { sandboxPrototype: contentWindow, wantXrays: true,
isWebExtensionContentScript: true })`). Two consequences:

- `globalThis` resolves to the **sandbox's own** global, so `globalThis.Object === Object` is
  **true** — the rollup shim tests exactly that, so in `old` it resolves to a real object and
  the `||` short-circuits.
- `self` is not an own property, so it is found on the prototype: the **Xray-wrapped page
  window**, whose `Object` is the page's. So `self.Object === Object` is **false** in Firefox
  (realm split; Bugzilla 1523139, WONTFIX).

Chrome has one realm, so `freeSelf` is truthy there and the third operand is never evaluated —
with or without a shim. Hence a Firefox-only failure from a bundler change.

## Why it went unnoticed for a year

`Function(...)` was **in the 1.0.1 bundle the whole time**, at byte 6722 in this repro's
`old` build too. It was simply unreachable: `||` does not evaluate its third operand while
the first is truthy. Code present is not code executed — which is why a grep for `Function(`
over the old bundle would have found it and meant nothing.

## What this does not establish

- The app's own two releases were also checked directly (v1.0.1 pinned vite 6.3.5 / rollup
  4.41.1 and had the shim; v1.1.0 pinned vite 8.1.0 / rolldown 1.1.3 and had none). Those
  builds are not archived here — this directory is the minimal form of the same finding, and
  the version numbers differ from the table above because wxt resolves today's transitives.
  What is pinned here is the wxt version, which is the variable.
- No original xpi was loaded into a browser for this record. The failure is reproduced from
  the emitted bundles plus a model of Firefox's sandbox, and corroborated by the console
  output from the real incident.
- "The wxt bump is what changed it" rests on these two versions. The mechanism (rollup emits
  a `global` shim, rolldown does not) is what the byte slices show; whether every version in
  between flips at one specific release was not bisected.

## Fix

In the application repo: lodash was dropped for `es-toolkit` (its `keyBy`, and `throttle`
with the default leading+trailing edges, which match lodash's), and a `scripts/csp-guard.ts`
build gate now fails the build if the emitted bundles contain an `eval`/`Function` call or
`'unsafe-eval'`. The guard is deliberately conservative — it flags any occurrence, reachable
or not, because reachability is not tractable statically and a silently broken Firefox
release costs far more than a false alarm.
